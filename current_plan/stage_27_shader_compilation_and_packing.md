# Этап 27. Компиляция, рефлексия и упаковка шейдеров (Shader Compilation & Packing)

**Статус:** 🚀 В работе

> [!IMPORTANT]
> Этот файл — единственный источник истины для Этапа 27.
> В рамках этапа реализуются:
> 1. Кроссплатформенная компиляция HLSL-шейдеров через DirectX Shader Compiler (DXC) в байткод **DXIL** (для DirectX 12) и **SPIR-V** (для Vulkan).
> 2. Автоматическое извлечение рефлексии шейдера (Shader Reflection):
>    - Входные вертексные атрибуты и автоматическое вычисление маски требуемых стримов меша (`requiredStreamsMask`: Stream 0 Base, Skinning, Colors, UV1);

> 3. Бинарный формат упакованного шейдера (`ShaderBlobHeader`, стадии VS/PS, поддержка платформ DXIL/SPIR-V).
> 4. Интеграция в сборщик ассетов (`assets_builder_dll`): `ShaderImporter`, валидация и упаковка в `data.dat` под типом `eDataDatType::Shader`.
> 5. Рантайм-десериализация `ShaderData` в `core` для последующего использования в Материалах (Этап 29) и PSO (Этап 30).

## 1. Архитектурный контекст и цели

Шейдер — это первоисточник требований к геометрии:
- Именно **Вершинный Шейдер (Vertex Shader)** через свои входные семантики (`POSITION`, `NORMAL`, `TANGENT`, `TEXCOORD`, `COLOR`, `BLENDINDICES`) диктует, какие входные данные ему необходимы.
- На основе рефлексии шейдера вычисляется битовая маска требуемых стримов меша:
  ```cpp
  enum class eMeshStreamFlags : uint32_t
  {
      None         = 0,
      Stream0_Base = 1 << 0, // Pos(12) + Norm(12) + Tan(16) + UV0(8) = 48b
      Stream1_Skin = 1 << 1, // BoneIndices + BoneWeights
      Stream2_Color= 1 << 2, // RGBA8
      Stream3_UV1  = 1 << 3  // float2
  };
  ```
- Материал хранит ссылку на Шейдер и мгновенно наследует его маску требований.
- Сборщик мешей (`Stage2_PackPlanner`, Этап 28) считывает эту маску из материалов и пакует в `data.dat` только нужные стримы без лишних байтов.

## 2. Компилятор шейдеров (DXC) и таргетинг платформ

Проект уже имеет настроенный `dxcapi.h` и бинарные библиотеки DXC (`.cache/dxc-src/`):
- Для **DirectX 12**: профиль `vs_6_0` / `ps_6_0` $\to$ компиляция в **DXIL**.
- Для **Vulkan**: профиль `vs_6_0` / `ps_6_0` с флагом `-spirv` $\to$ компиляция в **SPIR-V**.

Компилятор вызывается в сборщике (`assets_builder_dll`), формируя байткоды для целевых графических API.

---

## 3. Рефлексия шейдера (Shader Reflection)

Сборщик извлекает метаданные из скомпилированного шейдера (через `IDxcUtils` / `ID3D12ShaderReflection` / SPIR-V reflection):
1. **Входная сигнатура вершин (Vertex Input Signature):**
   - Анализ семантик:
     * `POSITION`, `NORMAL`, `TANGENT`, `TEXCOORD0` $\to$ `Stream0_Base`;
     * `BLENDINDICES`, `BLENDWEIGHT` $\to$ `Stream1_Skin`;
     * `COLOR` $\to$ `Stream2_Color`;
     * `TEXCOORD1` $\to$ `Stream3_UV1`.
   - Результирующая маска `requiredStreamsMask` записывается в заголовок шейдера.
2. **Параметры и ресурсы:**
   - Список константных буферов (имя, размер, слот привязки `b0`, `b1`...);
   - Список текстур и сэмплеров (имя, слоты `t0`, `s0`...).

---

## 4. Бинарный формат упакованного шейдера (`ShaderBlobHeader`)

В `data.dat` шейдер записывается как непрерывный бинарный блоб:

1. **Заголовок `ShaderBlobHeader` (64 байта):**
   - Сигнатура `"ZSH"` (Zzz Shader);
   - Версия формата (`1.0.0`);
   - Битовая маска платформ (`PlatformDXIL`, `PlatformSPIRV`);
   - `requiredStreamsMask` (`uint32_t`: маска необходимых стримов геометрии);
   - Смещения и размеры байткодов для каждой стадии:
     * `vsOffset`, `vsSize` (Vertex Shader);
     * `psOffset`, `psSize` (Pixel Shader);
   - Смещение и размер блока метаданных рефлексии (Uniforms / Buffers / Bindings).
2. **Блок рефлексии (Reflection Metadata):**
   - Таблица параметров (для связки с Материалом).
3. **Блок байткодов:**
   - Байткод VS;
   - Байткод PS.
