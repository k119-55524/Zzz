# Этап 27. Компиляция, рефлексия и упаковка шейдеров (Shader Compilation & Packing)

**Статус:** 🚀 В работе

> [!IMPORTANT]
> Этот файл — единственный источник истины для Этапа 27.
> **Главный принцип:** Скомпилированный шейдер — это **готовый бинарный «экзешник» для GPU**, который в рантайме игры **напрямую без компиляции и парсинга отдаётся с диска видеокарте**:
> - Для **DirectX 12** $\to$ бинарный **DXIL** передаётся прямо в `D3D12_SHADER_BYTECODE`;
> - Для **Vulkan** $\to$ бинарный **SPIR-V** передаётся прямо в `vkCreateShaderModule`;
> - Для **Metal** $\to$ бинарный **metallib** передаётся прямо в `device->newLibrary(data)`.
> 
> Никакого компилятора в рантайме, никаких текстовых парсеров, нулевые задержки при старте игры!

---

## 1. Архитектурный контекст и цели

Шейдер — это первоисточник требований к геометрии:
- Именно **Вершинный Шейдер (Vertex Shader)** через свои входные семантики (`POSITION`, `NORMAL`, `TANGENT`, `TEXCOORD`, `COLOR`, `BLENDINDICES`) диктует, какие входные данные ему необходимы.
- На основе рефлексии шейдера вычисляется битовая маска требуемых стримов меша:
  ```cpp
  enum class eMeshStreamFlags : uint32_t
  {
      None         = 0,
      Stream0_Base = 1 << 0, // Pos(12) + Norm(12) + Tan(16) + UV0(8) = 48b
      Stream1_Skin = 1 << 1, // BoneIndices + BoneWeights
      Stream2_Color= 1 << 2, // RGBA8
      Stream3_UV1  = 1 << 3  // float2
  };
  ```
- Материал хранит ссылку на Шейдер и мгновенно наследует его маску требований.
- Сборщик мешей (`Stage2_PackPlanner`, Этап 28) считывает эту маску из материалов и пакует в `data.dat` только нужные стримы без лишних байтов.

## 2. Конвейер компиляции и защита от багов кросс-платформенности

Исходный язык всех шейдеров в проекте — **чистый HLSL (Shader Model 6.0+)**.
Сборка вынесена в отдельную статическую библиотеку **`shader_builder`** (`src/shader_builder/`), которая компилирует шейдеры в целевые бинарники без текстовых рантайм-тормозов:

1. **DirectX 12 (Windows / Xbox):** `HLSL` $\xrightarrow{\text{DXC}}$ **DXIL** (`vs_6_0`, `ps_6_0`).
2. **Vulkan (Windows / Linux / Android):** `HLSL` $\xrightarrow{\text{DXC -spirv}}$ **SPIR-V** (`vulkan1.2`).
3. **Metal (macOS / iOS) — Полная компиляция:** 
   $$\text{HLSL} \xrightarrow{\text{DXC -spirv}} \text{SPIR-V} \xrightarrow{\text{SPIRV-Cross}} \text{MSL} \xrightarrow{\text{metal.exe / xcrun metal}} \textbf{.metallib (чистый бинарный архив)}$$
   *В `data.dat` всегда попадает чистый бинарный байткод под целевую платформу для мгновенной передачи в GPU без парсинга текста.*

### 🔒 3 правила защиты от багов перекодировки (Обязательно к соблюдению):

1. **Детерминированный маппинг слотов привязки (Binding Slots):**
   Чтобы номера слотов ресурсов совпадали на всех платформах и не путались между дескрипторными сетами:
   - Константные буферы (`b0..b99`) строго маппятся на слоты `0..99`;
   - Текстуры (`t0..t99`) строго маппятся на слоты `100..199`;
   - Сэмплеры (`s0..s99`) строго маппятся на слоты `200..299`.
2. **Единый порядок упаковки матриц (Matrix Layout):**
   В кодовой базе C++ и в шейдерах HLSL фиксируется единый стандарт порядка матриц с явным флагом компилятора DXC (например, Column-Major `-Zpc` или Row-Major `-Zpr`), исключающий транспонирование при умножении.
3. **Единый диапазон глубины Z:**
   DirectX 12, Vulkan и Metal используют один и тот же стандарт диапазона глубины: строго $[0.0, 1.0]$. Никаких пересчётов Z в шейдерах не требуется.

## 3. Рефлексия шейдера (Shader Reflection)

Сборщик извлекает метаданные из скомпилированного шейдера (через DXC Reflection API):
1. **Входная сигнатура вершин (Vertex Input Signature):**
   - Анализ семантик:
     * `POSITION`, `NORMAL`, `TANGENT`, `TEXCOORD0` $\to$ взводит флаг `Stream0_Base`;
     * `BLENDINDICES`, `BLENDWEIGHT` $\to$ взводит флаг `Stream1_Skin`;
     * `COLOR` $\to$ взводит флаг `Stream2_Color`;
     * `TEXCOORD1` $\to$ взводит флаг `Stream3_UV1`.
   - Результирующая маска `requiredStreamsMask` записывается в заголовок шейдера.
2. **Параметры и ресурсы:**
   - Список константных буферов (имя, размер, слот привязки);
   - Список текстур и сэмплеров (имя, слоты, размерности).

## 4. Бинарный формат упакованного шейдера (`ShaderBlobHeader`)

В `data.dat` шейдер записывается как непрерывный бинарный блоб:

1. **Заголовок `ShaderBlobHeader` (64 байта):**
   - Сигнатура `"ZSH"` (Zzz Shader);
   - Версия формата (`1.0.0`);
   - Битовая маска целевого GAPI (`eShaderBinaryFormat: DXIL, SPIRV, MetalLib`);
   - `requiredStreamsMask` (`uint32_t`: маска необходимых стримов геометрии);
   - Смещения и размеры байткодов для каждой стадии:
     * `vsOffset`, `vsSize` (Vertex Shader);
     * `psOffset`, `psSize` (Pixel Shader);
   - Смещение и размер блока метаданных рефлексии (Uniforms / Buffers / Bindings).
2. **Блок рефлексии (Reflection Metadata):**
   - Таблица параметров (для связки с Материалом).
3. **Блок байткодов стадий:**
   - Байткод VS (готовый binary);
   - Байткод PS (готовый binary).
